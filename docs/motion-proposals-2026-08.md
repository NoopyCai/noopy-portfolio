# 夜車・區間 · 前端動畫深化提案

> 2026-08 研究。範圍:盤點既有動態的完成度,提出讓列車與畫面更有質感的動畫方案。
> 原則:所有提案要在「台鐵夜車」的語言裡成立;質感 > 花俏;**不加新依賴**;每項標注 reduced-motion 降級。
> 核心判斷:**這頁目前所有動態都是「使用者驅動」的(捲動/滑鼠/點擊),沒有一個是「世界自己在動」的。使用者一停下來,整個場景就變回一張照片——這才是質感缺口的根源,不是動態不夠多。**

## §2a 環境/氛圍層(idle 時也在動的)

### A1 · 時間驅動的行進底噪(車體微晃)★
既有 sway rAF 疊兩三個互質週期的 sin(縱搖+橫搖),模擬轉向架。振幅原則:小到讀不出「在動」,只讀得出「不是靜止的照片」。
**過掃描餘裕實測**:sway `scale(1.035)` 垂直總餘裕 ~27px,滑鼠已吃 ±12px → **底噪垂直振幅 ≤3px**;水平餘裕充裕(±25px),底噪優先走水平與 rotate。
與 audit §4.6 的張力:加了時間項 ride 期間 rAF 永不收斂——折衷:ride 跑、gate/exit/`document.hidden` 休眠。
**影響力:極高 / 工時:S / 效能風險:極低 / 不需等 §4.3**

### A2 · 窗景的自走流速(車一直在開)★
`pan = x + accumulatedTime * v`,停止捲動窗景仍緩慢流動。`v` 隨 B1 的速度曲線變化(到站→0)。
**卡在 audit §4.3**:blit 目前靠 setP 每幀 re-render 推動,自走必須改訂閱 rAF/ref 通道。gate 在 `phase==="ride"` + visible。
**影響力:極高 / 工時:M / 效能風險:中 / 依賴:§4.3**

### A3 · 中央窗的多層視差(近景比遠景快)
`drawScene` 加 layer 參數輸出 far/near 兩層,blit 給不同速度(0.35/1.0)。**只做中央窗**(左右窗 7% 寬看不出來)。快取 12→18 張(+2.5MB)。
效果必須建立在 A2 之上,**排在 A2 之後,不要先做**。
**影響力:高 / 工時:L / 依賴:§4.3 → A2**

### A4 · 車廂日光燈的微顫(不是頻閃)
獨立暖色 overlay,opacity 0–0.02 以 5–7 秒不規則週期漂移;每 20–40 秒一次 80ms 微弱下沉。
**紅線:WCAG 2.3.1 三閃光門檻,>3Hz 的亮度變化絕對禁止;永遠不要做「日光燈啟動閃爍」。**
**陷阱:不要動 `grade.filter`**(有 .8s transition 會抹平且與換站打架),用獨立 overlay 的 opacity。
**影響力:中高 / 工時:S / 無依賴**

### A5 · 隧道段(站與站之間的事件)★
站間中點(dist≈0.5,資訊卡不可見的 32% 區間)放一段短隧道,由 `rideProgress` 插值 → 天然可倒放:進洞(窗景 opacity→0.06 + 垂直暗帶掃過)→ 洞中(LED 相對變亮 + 暖色光帶橫掃車廂內壁)→ 出洞(回光 180ms)。
附加價值:這是「車內比車外亮」(audit §3.1 光線反轉)唯一合理成立的場景。
**紅線:隧道要短(≈ride 的 6%),絕不能與資訊卡可見區間重疊。**
**影響力:極高 / 工時:M / 無依賴**

### A6 · 車窗玻璃的實體感
每扇窗疊靜態 CSS 反光帶+邊角水氣(gradient),隨滑鼠比車廂多走 3–4px → 玻璃位在你和景之間。零動畫預算換最大實體感。
**影響力:中高 / 工時:S**

### A7 · LED 光暈呼吸
排在 audit §4.2(跳針/重啟/CJK)修好之後,否則是把讀起來壞掉的元件做得更亮。**影響力:低**

### ❌ A8 · 窗外雨滴/霧氣——不做
像素風語言衝突、需要常駐粒子 rAF(本頁最不該加的)、六站敘事沒有雨的動機。A6 給 80% 效果、1/50 成本。

## §2b 捲動敘事層

### B1 · 到站減速的速度曲線重映射 ★★(投報率最高的單一改動)
現況 `x = rp * (n-1)` 是**線性**——「到站」在物理上根本沒發生。audit §4.2 的「四個時長對齊」只治症狀:速度曲線不減速,對齊了也還是等速衝過月台。
做法:`lib/progress.ts` 加 `stationEase(x)`(每個整數站點附近壓平的 per-segment S 曲線),同時驅動窗景流速、資訊卡可見窗口、LED 報站時機。
**必須一起改 `jumpTo` 的反算**;`progress.test.ts` 加三條(端點不動、單調、端點導數→0)。
**影響力:極高 / 工時:S / 效能風險:零 / 無依賴**

### B2 · 月台進站(窗外真的有站)
`dist → 0` 時中央窗疊入 platform 場景近景切片(scene.ts 資產已存在),隨 B1 減速滑進來停住。**依賴 B1**(等速滑過去比不做更假)。
**影響力:極高 / 工時:M / 依賴:B1**

### B3 · gate 相位不是虛空
audit §5.4 的動態深化。**不要讓月台平移**(你站著等車,月台不該動)。正確的動態:頂棚燈微顫(複用 A4)+ 每 8–12 秒一次「對向列車通過」的橫向亮帶(1.2s)。
**影響力:高 / 工時:M**

### B4 · exit 相位的分節(停穩 → 起身 → 停半拍 → 轉身)
現況 rise 與 turn 重疊 0.10,揉成一個連續動作。改:ride 尾段 10% A1 振幅→0(停穩)→ 起身(e 0–0.40)→ **半拍停頓(e 0.40–0.48,什麼都不動)** → 轉身。停頓半拍是全站最便宜的敘事升級:兩個 clamp 區間的數字。
建議與 audit §4.4(blur→crossfade)一起做。
**影響力:高 / 工時:S / 依賴:A1(振幅收斂那半)**

## §2c 微互動層

### C1 · 路線圖上的列車標記 ★
整頁沒有任何元件呈現「連續進度」。在路線圖縱線上放小標記(琥珀方塊/迷你 train icon),`top` 由連續的 `x` 驅動,配合 B1 自然有減速節奏。**坑 3:路線圖不能進 sway 層,現在位置是對的。**
**影響力:高 / 工時:S**

### C1b · 點擊路線圖的確認回執
`::after` 擴散圓環(260ms)。解決跳站 1200ms 期間「我按到了嗎」。**工時:S**

### C2 · 跳站的「快轉」
smoothScrollTo 期間窗景流速 ×2.5 + 極淡水平速度線(不用 blur)。**依賴 A2 + 必須先修 §4.5(smoothScrollTo 不可中斷)**。
**影響力:中高 / 工時:M**

### C3 · 資訊卡鏡面高光隨滑鼠
`.glasscard::before` 的 135deg 換成 CSS 變數由指標驅動(複用 sway 滑鼠值,零新監聽)。Liquid Glass 語言裡最正統的一招。手機無 hover,不能是唯一回饋。
**影響力:中 / 工時:S**

### ❌ C4 · Flip 做 modal 從按鈕展開——不做
祖先鏈有 rotateY/scale/perspective,Flip 的 getBoundingClientRect 量測會被 3D transform 污染。力氣花在 modal 真正缺的 Escape/focus trap(audit §9.2)。

## §2d 文字動效

### D1 · LED 報站的「逐列刷新」
真實台鐵 LED 切換訊息是整條逐列刷新不是滑動:`mask-position` 橫掃 220ms。前提是 §4.2 一起動 LedSign。**工時:S**

### D2 · 站名逐字點亮
只在 `.sp-station`(LED 站名)做。首選**純 CSS 元素級 stagger**(`animation-delay: calc(var(--i)*60ms)`,已達 80% 效果);SplitText 次選(有 DOM 拆建成本)。**`sp-body` 的內文絕不逐字**,那是噪音。
**工時:S**

### ❌ D3 · metrics 數字滾動——不做
六站 metrics 資料是空的(CLAUDE.md 明文)。沒有數字可以滾。等 §7.1 補真數據,屆時 gsap core 就夠。

## §2e 3D 加碼(共用已付費的 three chunk)

**結構性理由,大部分不值得:**
1. chunk 已付費 ≠ 執行成本已付費——ride 階段用 3D 會把一次性成本變**常駐 WebGL + 常駐 rAF**。
2. 門場景核心價值是末幀對位(dx=0),ride 階段重啟 3D 就要再解一次對位。

### ✅ E1 · 出站的門(反向複用 door3d)★
進站有 95% 完成度的 3D 門,出站只有 CSS transform——結構不對稱。讓 `Door3D` 在 exit 相位反向再出場(相機反向 dolly、門由開到關、光楔從月台側灑入)。
幾乎零成本的原因:元件永不卸載(同一個 context)、render 是純函式(餵 `exitDoorProgress` 就畫)、倒放已驗證、**出站門外是 Concourse 純色底,不用重解對位**。
建議與 audit §4.4 一起做(同一段相位)。
**影響力:極高 / 工時:M / 效能風險:零新增**

### ❌ E2 · 3D 月台掠過——不做
B2 的 canvas 疊層 80% 效果、1/10 成本、不用喚醒 WebGL。

## §3 技術選型原則

18 項提案**一個新依賴都不加**:CSS / 既有 rAF / 純數學 / canvas / 既有 three chunk。GSAP 全套 plugin 已免費且在 node_modules,但只有 D2 次選會用到一個——core + ScrollTrigger 已在 bundle,多引一個 plugin 就多一份 JS。

## §4 三條紅線

1. **WCAG 2.3.1**:所有亮度變化 <3Hz(A4/A5/B3)。
2. **sway 過掃描餘裕**:底噪垂直振幅 ≤3px。
3. **常駐迴圈 gating**:時間驅動動態必須在非 ride、`document.hidden`、reduced-motion 三種情況停止。

## §5 reduced-motion

多數項目走 StaticFallback 天然免疫。要處理的:rAF 類整段不啟動(且 mount-once 檢查要改成 `mq.addEventListener`);玻璃/高光保留靜態只關滑鼠位移;C1 改離散跳位;CSS 動畫加 `animation: none` 且**不能靠動畫才顯示內容**(`opacity:0` 起手 + JS 沒跑 = 內容永久消失)。

## 補充(4/4):外部案例與技術來源(節錄)

- **可引用案例**:Sébastien Lempens(Awwwards SOTD,捲動第一人稱載具旅程,結構同本站)、ZERO(Codrops 拆解:單一 virtual scroll 標量驅動一切 —— 背書本站 progress 0→1 的設計)、The Deep Sea(對照組:不用 WebGL 也成立)。**查無任何火車/鐵道主題的得獎站 —— 本主題在得獎作品裡是空白。**
- **WCAG 2.3.1 官方數字**(A4 紅線的背書):≥3Hz 即危險;341×256px 是安全面積上限(全視窗 overlay 必然超過);相對亮度變化 10% 是「一般閃光」門檻。A4 的 0.15–0.2Hz/2% 是非常保守的安全值。「日光燈啟動閃爍」在這頁的尺寸下明確違反 Level A,永遠不要做。兜底寫法:`@media (prefers-reduced-motion: reduce), (update: slow)`。
- **GSAP 官方確認全免費**(3.13 起,gsap.com/blog/3-13);SplitText 3.13 起體積減半+自動 aria-label,D2 次選上調為「可考慮」,純 CSS 仍首選。**GSAP Observer 是 audit §4.5(smoothScrollTo 不可中斷)與 §8.5(無觸控手勢)的共同解。**
- **CSS scroll-driven animations 現況**:Chrome/Edge/Safari 已支援(Safari 26.4 起跑 compositor thread),**Firefox 正式版尚未支援**(caniuse 的 156 是 Nightly)。核心 pin+scrub 無法替代(它做不了 pin);但 C1 列車標記與 Concourse reveal 可用 `@supports` 漸進增強卸到 compositor。降級紅線:起始態不能 `opacity:0`。
- **雨滴維持不做**:RainyDay.js 是 GPL(不能碰)、WebGL 折射要開第二個 context(撞坑 10)。退路:純 CSS(codepen lbebber)。
- **標記一個超出本報告的大問題**:Val Head(Smashing)的「reduced ≠ none」—— `StaticFallback` 整頁另做的策略可能方向就錯了,正解也許是「同一趟車,把 sway/隧道/轉身換成 crossfade」。待議。
