## 全局約束

- 手寫 three(不上 R3F,論證見研究 §6);**render-on-demand 是憲法**——場景無時間軸,`render(x)` 只在捲動/resize/貼圖到貨時被叫;時間項(A1 微晃、滑鼠視差)永遠留在 canvas 的 CSS transform(sway 層),WebGL 零重繪。
- **文字永不進 WebGL**(坑 3 升級版):LED、資訊卡、路線圖、控制鍵、Concourse 全程 DOM。
- 像素素材貼 3D 平面必須 `NearestFilter` 且平面正對相機(像素不能吃透視收斂)。
- 每階段結束:tsc + tests 綠、build 照 CLAUDE.md 順序、真機驗收(0+1 合驗)。
- **前置:燈光曲線那批(工作區未 commit 的 9 檔)必須先驗收 commit**,階段 0 才動工(檔案重疊)。

## 階段 0:捲動標量 ref 通道重構(audit §4.3)

**目標**:連續值不再經過 React re-render。`onUpdate` 直寫 ref/CSS 變數/render(x),`setState` 只留離散值。

- 連續(每幀,直通 DOM/場景):`p`→`x`(eased)、`pan`、`doorP`、grade 三數值、camera transform、tunnel/platform 插值 → 集中到一個 `applyFrame(p)`(非 React 函式),由 ScrollTrigger `onUpdate` 直呼。
- 離散(才 setState):`index`(站切換,驅動資訊卡內容/LED 文字)、`phase`、`panelVisible`。
- `Window` 的 blit、`CabinComposite` 的 grade/tunnel/platform 樣式改成 `applyFrame` 內 imperative 寫入(ref 傳遞)。
- `Door3D.render(doorP)` 由 applyFrame 直呼(不再走 prop+useEffect)。
- **驗收 = 視覺零變化**:重構前後同捲動位置逐格截圖 diff;React DevTools 確認捲動時零 re-render;既有 25+ tests 全綠。

## 階段 1(L1):cabin 拆層視差 + 窗景深度層

### 素材(✅ 已完成,2026-08-13;原 inpaint/差分方案作廢)

實際走了**換基底**路線(使用者的工具是整張重生成、非嚴格 inpaint,差分不可行;實測差異 36%):
- `public/cabin.jpg` 已換成新無立柱基底(2715×1528、344KB、比例誤差 0.00004%),WIN/LED_RECT 已重量(差 ≤0.2%),門場景末幀對位實測 dx 0.02px。
- `public/cabin/cabin-front.png`(2715×1528 RGBA、120KB):立柱+橫杆 alpha 層,由使用者的綠幕圖去背(alpha + flood-fill 交叉檢查)。**已產出但未接 DOM** —— 接入是本階段(視差)的工作。
- 母檔 `docs/assets/cabin-front-green.png`;完整決策與 SOP 見 `docs/ai-illustration-prompts.md` §E。

### 實作

- `CabinComposite`:img 改兩層(back 沿用現有 cover 幾何;front 同幾何疊上)。
- sway 迴圈:front 層視差係數 **1.7**(滑鼠 ±15px 時多走 ~10.5px);**front 層自帶 scale 1.06**(過掃描:1.035 的餘裕不夠近層多走的位移,係數與 scale 的乘積要重算並在註解記錄)。A1 底噪同係數放大。
- 直式手機:係數隨 aspect 降(cover 裁切下近層位移比例更大),390×844 實測定案,立柱不得露出畫面邊。
- 窗景深度層 = A3 原案:`drawScene` 加 `layer: "far" | "near"`,中央窗兩層 blit(far 0.35× / near 1.0×),快取 12→18 張;左右窗不拆。
- 門過場零改動(交棒瞬間 sway 位移趨近 0,兩層疊合 = 原圖)。

**驗收(與階段 0 合驗)**:視差最大位移下立柱邊緣無 inpaint 痕跡;疊層靜止時與原圖無差;fallback(front 載入失敗)= 只顯示 back,仍完整可用;reduced-motion 層疊回原圖。

## 階段 2(L2a):門場景吞下 ride

**分鏡變更**:doorP=1 時 canvas **不再淡出**(移除 0.85–1.0 的 crossfade),相機停在車廂內,場景成為 ride 的視覺層;DOM 車廂不再掛載(降級路徑除外)。

### 場景構成(z 由近到遠)

| z | 物件 | 素材 | 動態 |
|---|---|---|---|
| -6.5 | 立柱+拉環平面(alpha) | cabin-front.png | 相機視差天然 |
| -8 | 牆+座椅+窗洞平面 | cabin-back.jpg(窗區 alpha 挖洞,實作時程序處理) | grade 場景光 |
| -9.5 | 月台層平面 | platform strip(CanvasTexture) | opacity = f(dist)(B2 邏輯平移) |
| -11 / -14 | 窗景近/遠層平面 | drawScene strips(CanvasTexture、NearestFilter) | `texture.offset.x = f(x)`(pan 平移;A3 視差 = 兩層深度天然結果) |

- 站切換 crossfade:窗景平面各兩張 texture 疊 opacity(等價現有 SceneLayer 雙層)。
- 隧道:A5 從 CSS overlay 改場景光/光片——掃光沿 z 有先後(近層先亮),參數仍由 eased x 插值。
- 燈光:AmbientLight+PointLight 的顏色/強度由數值 Grade 映射(燈光曲線的插值結果直接餵);窗景平面自發光(MeshBasicMaterial),「車外亮於車內」成物理事實。
- **LED 與 canvas 同進 sway 層維持現狀;資訊卡/路線圖 DOM 不動。**
- 效能預算:<30 draw calls、<500 tri、overdraw ≤4×、手機 dpr 1.5;`stats()` 擴充回報。

### 降級(Q3a:降規格凍結)

- `createDoorScene` 回 null / three chunk 載入失敗 → 掛**精簡 DOM 車廂**:cabin.jpg 單層 + 三窗 blit + 資訊卡 + LED,**無隧道/月台層/門過場**(直接切換)。
- 現有 CabinComposite/Window 保留為此路徑,砍掉 tunnel/platform props;**靜默降級,不顯示任何提示**(Q8a)。
- 文案/座標同步面:資訊卡與 LED 是共用 DOM,零同步成本;需同步的只剩 cover 幾何常數(註解互相指向)。

**驗收(單獨)**:六站全程 + 隧道 + 月台 + 進站門在 WebGL 場景下走通;交棒消失(門開完無縫繼續);fallback 路徑走通;來回三趟無白屏 contextLost false;中階手機(或 CPU 4× throttle)捲動順暢;idle 時 GPU 零工作(DevTools 效能面板驗證)。

## 階段 3(L2b):exit 入景(一鏡到底)

- 刪 `.camera` 的 CSS `rotateY/translateX` 假 3D;exit 相機在場景內真實 yaw + 位移(由 e 插值,無時間軸)。
- 分鏡:停穩(A1 calm)→ 起身(相機升高+俯角回正)→ 半拍 → 轉身(yaw,立柱/座椅/窗框真視差)→ 看見門(場景內既有 exit 門)→ 門關上 → canvas 淡出交棒 Concourse(唯一保留的 DOM 交棒,對面是純色底,無對位問題)。
- B4 的節奏常數(0.40/0.48)平移;E1 的門閉合分鏡吸收(不再需要 `.camera`/Door3D 錯開交棒)。
- 資訊卡/路線圖在 exit 開始即淡出(現狀不變)。

**驗收(單獨)**:轉身過程立柱視差可見、無穿幫;倒捲完整倒放;直式構圖(門佔高 ~70% 的既有規格沿用);Concourse 交棒無縫。

## RWD(全階段)

- 視差/晃動係數一律 aspect 插值,不寫死;390×844 與 844×390 每階段各驗一輪。
- 觸控(hover:none):滑鼠視差 0、A1 底噪照跑(同現狀);L2 場景無 hover 依賴。
- 降級判定用能力(WebGL context 取得與否),不用 UA/寬度。
